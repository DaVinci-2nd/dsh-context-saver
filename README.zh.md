# dsh-context-saver · DSH 上下文节省插件

面向 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的发送端上下文裁剪插件。

它只在**把上下文提交给模型的那一刻**做裁剪，本地会话日志、聊天记录、轨迹视图全部保持完整。关闭插件或关掉全部选项后，发送的上下文与原始状态逐字节一致。

[English](README.md) | 中文

---

## 它解决什么问题

长会话真正贵的地方不是轮次多，而是每一轮都在重复搬运同样的东西：

- 模型的思考过程（reasoning / thinking）被逐轮回传，越滚越大；
- 同一个文件、同一个网页被反复读取，内容在上下文里出现三份、五份；
- 终端命令的完整输入参数被逐轮回传，而模型真正需要记住的只是输出；
- 很早以前的中间回合仍然占着位置，但早已不再影响当前决策。

本插件把这些内容从**发送副本**里剔掉，本地一份不少。

## 工作原理

DSH 的模型请求最终经过 `llm/stream` 瀑布事件，事件里携带即将提交的完整 `messages`。

插件在这个位置拿到请求，按已启用的规则生成一份新的消息数组，然后用 `ctx.llm.stream()` 重新派发这份请求。原请求是深冻结的，插件从不修改它，也不改动任何会话事件，因此：

- 本地会话日志、`session/event`、轨迹视图、导出记录：**全部是完整的**；
- 每次发请求时都基于全量本地记录重新计算裁剪结果；
- 裁剪是**确定性**的（同样的输入永远得到同样的输出），所以相邻两次请求的公共前缀逐字节一致，KV Cache 命中率基本不受影响。

### 为什么剔除不会让 DeepSeek 拒收

DeepSeek Messages 适配器对请求形状有硬性要求，插件输出的每一种结构都按这些要求设计，并已用真实 API 请求验证：

| 风险 | 处理方式 | 实测 |
|---|---|---|
| `tool_result` 找不到对应的 `tool_use` | **从不删除** `tool-call` 块，只把 `arguments` 置为 `{}` | 接受 |
| `tool_use` 后面没有紧跟结果 | **从不删除** `tool` 角色消息，只把内容清空 | 接受 |
| 思考块数量与本地 replay 元数据不一致 | **从不删除** `reasoning` 块，只把 `text` 清空，签名原样保留 | 接受 |
| 空的 thinking 块被拒 | 保留真实签名一起发送 | 接受（空内容 + 签名 / 空内容无签名 / 无 thinking 块，三种形状均返回 200） |

另外，压缩（compaction）与会话标题这类 `purpose` 请求不参与裁剪，避免改变它们自身的输入。

## 界面

控制项位于会话输入框工具栏（与「选择模型」「沙箱范围」同一排），点开后是一个浮动面板：

- **总开关**（默认开启）
- **剔除思考内容**（默认开启）——保留 think 块结构，清空其中内容；模型只收到正文
- **剔除重复获取的内容**（默认开启）——内容完全相同的文件 / 网页读取只保留第一次，后续只留标识与空结构
- **剔除终端运行的输入和过程**（默认关闭）——终端类工具调用只保留输出，去掉模型的输入参数
- **剔除上下文中部**（默认关闭）——开启时会弹出警告：*「剔除上下文中部可能会导致长上下文中间的重要内容在发送过程中缺失！」*
- **保留开头回合数**（默认 5，仅在开启中部剔除时生效）
- **保留结尾回合数**（默认 5，仅在开启中部剔除时生效）

支持中文 / English 两种界面语言，跟随 DSH 的语言设置。设置保存在本机，对所有会话生效：

```
$DSH_HOME/dsh-context-saver/settings.json
```

开关轨道使用固定的中绿色（开，`#22c55e`）与中性灰（关，`#9aa0a6`），不使用主题的 `brand-primary` / `border-l2`：这两个别名在暗色主题下分别解析成接近白色的 `#f9fafb` 与半透明白，白色滑块坐在上面看不出状态。

## 剔除上下文中部的规则

**1 回合 = 1 条用户消息 + 其后的模型输出**，因此回合边界由 `user` 消息划定。

设回合总数为 `N`、保留开头 `H`、保留结尾 `T`：

- 当 `N ≤ H + T` 时，**完全不剔除**（开头与结尾保留区重叠）；
- 否则，只有同时满足「不在开头 H 个之内」且「不在结尾 T 个之内」的回合会被剔除，这些回合的**结构保留、内容清空**（工具调用保留 id 与名称、参数置空；思考块保留位置与签名、文本清空；正文与图片清空），因此工具调用与结果的配对关系不会被破坏。

示例：17 回合、保留开头 7、保留结尾 8 → 保留第 1–7 与第 10–17 回合，剔除第 8、9 回合（`7 + 8 = 15`，共 15 个回合保留）。

> 提示：开头与结尾至少各保留 1 个回合。结尾那个回合承载着当前这次提问，清空它等于发出一个没有问题的请求；开头那个回合保证请求仍以用户消息开始。填入 0 会被自动抬到 1。

## 实测数据（真实会话）

两组独立测量，都打到官方 `deepseek-flash` 端点。

**本机一条真实的 65 回合会话日志**，按适配器自身的序列化规则、带上该会话自己的 34 个工具声明重放：

| | 提示词 token | 回复 |
|---|---|---|
| 未裁剪 | 867,787 | 接受 |
| **裁剪（默认配置）** | **574,347** | 接受 |

长会话下提示词 token 减少 33.8%，模型仍然正常回答。

**一条 60 回合、含大量重复读取的合成会话**，比较「产出第 N 回合的请求」与「产出第 N+1 回合的请求」以测量前缀复用：

| 配置 | 提示词 token | 缓存命中率 |
|---|---|---|
| 完全关闭裁剪 | 21,102 | 98.9% |
| **默认**（剔除思考 + 剔除重复读取） | **3,242** | **94.8%** |
| 默认 + 终端 | 3,242 | 94.8% |
| 默认 + 终端 + 中部 | 1,847 | 90.1% |

默认配置**发送的提示词 token 少 6.5 倍，缓存命中率 94.8%**，「90% 以上」的目标在所有配置下都成立。

## KV Cache 与命中率

- 已剔除的旧回合不会再被改写；新增回合只追加在结尾，因此公共前缀稳定。
- 重复读取的标记文本是固定的，引用的是「第几条工具结果」这个稳定序号，不会随会话增长而变化。短于 200 字符的读取不做替换，因为标记本身比内容还长。
- 开启「剔除上下文中部」后，回合会从「结尾保留区」逐步滑入「中部」，滑入的那一刻内容被清空，前缀缓存会从该处失效一次——这是任何中部裁剪方案都固有的代价，关闭该选项时不存在，所以该配置是 90.1%。
- 裁剪结果确定：完全相同的请求重发，实测两次都是 95.1%。

## 安装

### 从 GitHub 安装

```sh
dsh plugin add github:DaVinci-2nd/dsh-context-saver
```

要固定版本可钉住 commit：`dsh plugin add github:DaVinci-2nd/dsh-context-saver#<sha>`。

本插件是纯 JavaScript，没有构建步骤、没有 `prepare` 脚本，所以 git 安装**不需要任何 `allowBuilds` 放行**。

### 从本地目录安装

在插件管理界面选择该目录，或让 `install_bundle` 指向它。

### 安装后的插件行

```yaml
- insert:
    - id: dsh-context-saver
      name: dsh-context-saver
```

### 卸载

移除该插件行，或从插件管理里卸载 bundle。设置文件可手动删除。

## 目录结构

| 文件 | 作用 |
|---|---|
| `index.js` | Host 半部分：`llm/stream` 拦截 + 设置读写路由 |
| `src/trim.js` | 纯函数裁剪逻辑（无副作用，可单测） |
| `src/settings.js` | 设置默认值与读写 |
| `client.js` | 浏览器半部分：输入框工具栏控制项与浮动面板 |
| `locale/*.json` | 插件在插件管理中的标题与描述（中 / 英） |
| `test/trim.test.mjs` | 裁剪逻辑测试 |
